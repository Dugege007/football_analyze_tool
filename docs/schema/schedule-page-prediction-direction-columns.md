# 「当日赛程」页预测方向列与当日消息的格式（定稿）

状态：定稿。本文件的格式由用户在 2026-10-10 确认，替换了 v0.1.3 时的建议稿（原文件名 schedule-page-prediction-direction-columns-draft.md）。从 v0.1.5 开始实现。

## 页面布局

1. 「当日赛程」页保持清爽，作为总览和导航使用。每场比赛的「依据要点」不放在赛程页，仍然在「预测」页和比赛详情页查看。
2. 表格上方有一个「显示预测方向」开关。开关默认关闭，此时五个预测方向列折叠不显示；打开后，在「使用方案」列后面显示「亚盘」「欧盘」「大小」「竞彩」「竞彩让球」五列。开关状态保存在浏览器本地存储里（键名为 schedule.showPredictionColumns），下次打开页面时保持上一次的状态。
3. 表格上方有一个可以折叠的「当日消息预览」卡片，卡片标题右侧有「复制全部」和「只复制未开赛」两个按钮。消息只在页面上显示和复制，不会自动发送给任何人。

## 方向的来源

1. 每一列显示的方向，必须是当时确定下来的正式方案做预测时得到的方向，也就是正式库里冻结下来的预测记录。页面和接口只读取这些记录，不重新计算，也不改写。
2. 正式方案是指 strategy_defs 表里状态为 active、并且没有标记为测试用途的方案。影子方案和测试方案的预测不显示。
3. 亚盘方向来自 predictions 表；欧盘、大小、竞彩、竞彩让球的方向来自 prediction_legs 表里状态为 active 的记录，市场代码分别是 1x2、ou、jc_had、jc_hhad。到 v0.1.5 为止，只有亚盘有正式方案，所以另外四列目前都显示「-」。
4. 亚盘显示的盘口是结算盘口。结算口径为澳门临盘（macau_close）时，取正式库 odds_asian 表里澳门的临盘盘口。
5. 一场比赛的同一个玩法如果有多个正式方案下注，每个方案的方向都显示出来，中间用「 / 」分隔。

## 各列格式

| 列名 | 下注时的格式 | 示例 | 不下注 |
| --- | --- | --- | --- |
| 亚盘 | 「主」或「客」＋所下注这一方的盘口（雷速体育规则）＋空格＋「x」＋份数 | 「主+0.25 x1」「客-0.5 x2」 | 「-」 |
| 欧盘 | 「胜」「平」「负」中的一个或两个（双选时按胜、平、负的顺序）＋空格＋「x」＋份数 | 「胜 x3」「平负 x1」 | 「-」 |
| 大小 | 大小球盘口＋「大」或「小」＋空格＋「x」＋份数 | 「2.25大 x2」 | 「-」 |
| 竞彩 | 与欧盘相同的写法，指竞彩胜平负玩法 | 「胜 x3」「平负 x1」 | 「-」 |
| 竞彩让球 | 竞彩官方让球数＋「让」＋「胜」「平」「负」中的一个或两个＋空格＋「x」＋份数 | 「-1让负 x2」「+1让胜 x1」 | 「-」 |

## 符号规则

1. 库内约定：正式库 odds_asian 表的 handicap 字段是主队视角的盘口，主队让球记为正数，主队受让记为负数。例如 2026-06-06 的六208 葡萄牙对智利，澳门临盘在库里记为 2.0，表示葡萄牙（主队）让 2 球。
2. 亚盘显示按雷速体育的规则：加号表示所下注的这一方让球，减号表示所下注的这一方受让。因此下主队时，直接使用库里的数值并写出正负号；下客队时，先把库里的数值取相反数再写出正负号。例如库里是 2.0 时，下主队显示「主+2」，下客队显示「客-2」；库里是 -0.75 时，下客队显示「客+0.75」。盘口为 0 时显示「主0」或「客0」。
3. 竞彩让球显示按竞彩官方的规则：加号表示主队受让，减号表示主队让球，例如主队让一球写作「-1」。库里的竞彩让球线（odds_jc_hhad 表的 goal_line 字段和 prediction_legs 表的 line 字段）本身就是竞彩官方写法，所以原样显示，不做取反。
4. 大小球的盘口是总进球数，没有正负号，写在「大」或「小」的前面。
5. 以上转换只在一个函数里完成：web/src/api/pickFormat.ts 的 formatPick。网页表格和当日消息都调用这个函数，测试脚本是 web/scripts/test-pick-format.mjs（运行命令：在 web 目录执行 npm test）。

## 份数

1. 份数优先使用冻结预测里记录的份数（predictions.stake 或 prediction_legs.stake）。
2. 冻结预测没有记录份数（predictions.stake 为空）时，按「预测」页现有的推算口径计算：从依据要点里读出 dir_sum（或 bucket=SUM=）的绝对值，绝对值为 5 时推算为 2 份，绝对值为 3 时推算为 1 份，其他情况无法推算，只显示方向、不显示份数。这个推算写在后端 api/app/main.py 的 estimate_stake_from_rationale 函数里，与前端 web/src/api/messagePreview.ts 的 simplifiedStakeFromRationale 口径相同。
3. 推算出来的份数在表格里会在后面加一个星号「*」，鼠标停在上面会提示「冻结预测没有记录份数，份数是按预测页口径推算的」。当日消息里不加星号。到 v0.1.5 为止，正式库里正式方案的 12 条下注预测都没有记录份数，所以显示的份数全部是推算值。

## 当日消息

1. 仓库里没有定稿的日用消息模板：docs/schema/data-conventions-v1.md 第 4.3 节写明逐行模板等待分析师定稿，本机研究目录（不在仓库里）的 odds-data/schema/daily-prediction-dm-schedule.md 第 5 节只有草案。因此沿用草案的标题行和「每场一行」的写法，模板文件是 web/src/api/dailyMessageTemplate.ts。
2. 第一行是标题「【当日预测】竞彩日 年-月-日」。后面每一场下注的比赛占一行，写法是「- 竞彩编号 赛事 主队 vs 客队 开赛时间（北京时间）：下注方向」。下注方向只列下注的玩法，使用上面的格式，多个玩法之间用「；」分隔。不下注的比赛不列出。
3. 「复制全部」复制当天所有下注的比赛；「只复制未开赛」只复制按北京时间当前时刻还没有开赛的比赛（开赛时间晚于当前时刻）。开赛时间未知的比赛按未开赛处理。没有可以复制的比赛时，页面提示没有可以复制的场次。

示例（正式库 2026-06-06）：

```
【当日预测】竞彩日 2026-06-06
- 六204 日职联 横滨水手 vs 清水心跳 2026-06-06 16:00：主+0.25 x1
```
