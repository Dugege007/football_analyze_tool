## 目标时刻与几处默认值（2026-10-08 足球分析师定，回复 table-matches-api §12）
1. 例外场范围是 [23:00, 次日 11:30]（两端都含），见上一节。
2. 目标时刻严格按开赛前 8h 和 1h 算，精确到分钟，不再取整点。例如 18:30 开赛，中盘目标是 10:30，临盘目标是 17:30。开赛分钟不明（`kickoff_minute_known=0`）的场，仍然按整点。v2d3 的快照用补了分钟的开赛时间重新导出，只动副本、先备份；旧导出留作对照；已经冻结的预测不动。
3. 返还率基准：用本场之前的全部数据，至少 20 场，按「公司 × 阶段」分组。**旧手工档位中点换算出来的水位不算进基准**（只是近似值，会拉偏中位数）；只有真实水位的样本不到 20 场时，回退到固定的兜底阈值。多家平均里包含被评估的公司本身，同意，因为它只是参考列。`*_real` 只给原始值，同意。
4. 欧赔里标了 `api_closing` 的收盘价，报价时间不明，**不能当临盘用，也不参与返还率、凯利和高亮的计算**（可能晚于决策时点，属于泄漏）。只在完赛以后作为「收盘（时间未知）」参考展示，等拿到有明确时点的取值再说。
5. 澳门中盘的符号：在 v2d3 源头统一成「正数=主让」（先备份，只动副本），不能只靠同步脚本取反。同时加一条入库前的校验：同一场里同一家公司的中盘，如果跟初盘、临盘的正负号都相反，而且绝对值跟其中一个相同，就拦下来人工复核，不直接入库。

### 补充（2026-10-08，采纳算法顾问意见）
- 目标时刻改成精确到分钟后，指纹加 `phase_target=exact_minute`（旧的记 `hour_floor`）。重新导出后的回测和旧导出上的结果分开记账，不合并；已冻结的预测不动。
- 多家平均：页面上「多家平均（参考）」那一列照旧包含所有机构；凡是要算「某家偏离平均多少」的地方，一律改用**不含它自己**的其他几家的平均。快照里同时存参与平均的家数 `n_avg`。

## api_opening 的处理（2026-10-08 定）
- 取值优先级：同一家公司有带时间戳的最早一笔报价时，初盘用它（`open_basis=first_tick`，显示实际开盘时间）；只有 api_opening 时才用它（`open_basis=api_opening`）。
- api_opening 可以当初盘显示，也可以参与计算。初盘一定早于决策时点，不存在偷看未来的问题。显示时开盘时间写「时间未知」，并加灰色小字「API」做来源提示。
- 和 api_closing 的区别：api_closing 不知道是什么时候的价，可能晚于临盘，所以不进临盘；api_opening 只是缺少开盘时刻。
- 需要用到开盘时刻的地方（例如开盘到决策之间隔了多久、按开盘时间排序），遇到 api_opening 的场按「时间未知」处理，不能拿抓取时间顶替开盘时间。
- 影子和验证结果额外按 `open_basis` 分组出一份对照。如果 api_opening 那组和 first_tick 那组的命中率明显不同，再回头复查这条规则。
- 「即时（11:10）」是我们在 11:10 自己抓的快照，和 api_opening 是两个字段，不能互相顶替。（用户 2026-10-10 起不再把 11:10 快照当作一种盘口；11:10 自采快照仍然不能当初盘。）
- 补充（采纳算法顾问，2026-10-08）：「初盘一定早于决策时点」只在这家公司当时已经开盘的情况下成立。所以：
  - 同一家公司在决策时点之前（含决策时点）有带时间戳的报价（包括我们自己抓的「即时（11:10）」），api_opening 才能当初盘进特征；没有的话，这场的初盘按不可用处理（`unusable_reason=open_time_unknown_after_decision_possible`）。
  - 决策点按阶段分开判断：后端在初盘对象上给 `usable_at_mid`、`usable_at_close` 两个布尔值，再加 `earliest_ts_quote_at`（这家公司最早一笔带时间戳报价的时间，没有就是 null）。first_tick 的初盘两个值恒为 true。
  - 需要时间跨度的特征（例如初盘到中盘按每小时算的变化）遇到 api_opening 一律不算，不能用默认跨度去估。
  - 前端只读这两个标记，自己不做判断。任一个是 false 时，悬停写「初盘时间未知，可能晚于决策时点，不参与特征计算」。
  - 返还率、凯利、多家平均（2026-10-08 补）：api_opening 的初盘可以照常算出来显示，也可以参与高亮。但凡是这几个值要进特征或方案计算，就同样要过 `usable_at_mid` / `usable_at_close` 这道判断。理由不是「它一定早于决策时点」，这一点并不保证。

## 例外场判定改为按竞彩编号（2026-10-08，采纳算法顾问，取代上面「例外场范围」里的 11:30 上限）
- 有竞彩编号的场：属于竞彩日 D，且开赛时间不早于 D 日 23:00，就算例外场，不设次日 11:30 上限。规则中盘取 D 日 15:00，规则临盘取 D 日 22:00；（真实）列照旧记赛前 8 小时、赛前 1 小时。
- 没有竞彩编号的场（采集范围内的非竞彩场）：没有编号可依，仍按开赛时间落在 [D 日 23:00, 次日 11:30] 判，两端都包含。
- 理由：例外场是因为当晚 21:00/22:00 就要出预测，赛前 8 小时的时点没法操作。次日 12:00 开赛、但属于 D 的场同样符合这个理由。
- 影响：六008、二020、六036 改为例外场，这 3 行快照要重导，用到它们的 S1-V2 要重跑。后端排查 v2d3 里还有没有其他「属于 D、但次日 11:30 以后才开赛」的场，有的话一并处理。旧手工数据和已冻结的预测不动。
- 指纹记 `exception_rule=jc_code_ge_2300`（旧口径记 `time_window_2300_1130`）。
