## 0. 盘口术语（方案卡统一）

权威：[`../../schema/v2_0-odds-phase-terminology.md`](../../schema/v2_0-odds-phase-terminology.md)（2026-10-08 用户定完）。

| 中文 | 字段 | 含义 |
|---|---|---|
| 初盘 | `open` | **各家公司第一次开出的盘**（API 历史里该公司最早那条）；按公司分别取，并带实际开盘时间 |
| 中盘（规则） | `mid` | 默认＝赛前 8 小时；开赛 ≥23:00 例外场＝**当天 15:00**。分析／方案／结算默认用规则值 |
| 临盘（规则） | `close` | 默认＝赛前 1 小时；开赛 ≥23:00 例外场＝**当天 22:00**。分析／方案／结算默认用规则值 |
| 中盘（真实）／临盘（真实） | `mid_real`／`close_real` | 例外场另存：赛前 8h／1h；都带目标时间点与实际抓取时间。**只作对照**，默认不进主结论 |
| 即时盘口 | `live` | 比赛结束前任一时刻通过 API 抓到的当时盘口；中盘、临盘是其中两个固定时间点。其他时刻一律写「即时（抓取时间）」，必带抓取时间 |

- 「用临盘代替即时」**作废**：初盘、中盘、临盘分列。
- 竞彩日 **11:10** 快照＝「即时（11:10）」：字段 `live` + 抓取时间；指纹阶段可写 `live@11:10`。旧手工数据与 V3 对照继续用它；**不是**初盘。
- 非例外场不加「（规则）／（真实）」后缀：中盘／临盘就是赛前 8h／1h（`mid`／`close` 即可）。

## 1. 指标定义（与 summary 字段对齐）

| 字段 | 定义 |
|---|---|
| `n_eligible` | 观测窗内、具备该规则**全部数据依赖**且能结算的场次数（分母底座） |
| `hits` | 规则触发并产生方向（或 S8：触发「跳过」）的场次数 |
| `coverage` | `hits / n_eligible`（无 eligible 时记 `null`，勿记 0 掩盖缺数） |
| 结算（默认） | 澳门**临盘（规则）**（`close`）AH；赢侧水位 × **0.95**；走水单独计，不进胜负分母 |
| 特征冻结 | 只能用决策阶段及以前的盘／水／模型输出；指纹须写明特征阶段（`open`／`mid`／`close`／`mid_real`／`close_real`／`live@…`）；禁止用结算盘或赛后信息调阈值 |

建议后端 `validate`/`compare` summary 直接用上述三键；现有 `signal_count`/`n` 可映射为 `hits` / `n_eligible`，定稿后对齐一次即可。

### 1.1 CLV 三列（平博；分析师已同意）

全部以**平博**盘口为准；指纹写明用哪一列；三列样本**不合并**。

| 列 | 对照盘 | 说明 |
|---|---|---|
| **CLV（规则）** | `close` | **主口径**。例外场的 `close`＝当天 22:00，故本列衡量的是相对 22:00 盘的优势 |
| **CLV（真实）** | 例外场用 `close_real`；非例外场与规则列相同 | 评估是否跑赢市场看本列 |
| **CLV（收盘）** | 平博 `last_prematch`（开赛前最后一条即时；带抓取时间与 `minutes_before_kickoff`） | **没有就留空（null）**，不拿 `close`／`close_real` 顺延顶替 |

统计规则：

1. **新鲜度门槛（暂定 15 分钟，待平博快照密度统计复核）**：仅 `0 < minutes_before_kickoff ≤ 15` 有效；>15 标 `stale`、**不计入** CLV（收盘）；开赛后的快照不算。  
2. **覆盖**：CLV（收盘）单独报覆盖场数（有合格 `last_prematch` 的场／eligible）。  
3. **三列互比**：只在三列都有值的同一批场上比。

## 2. 互斥分桶（默认实验设计）

**原则**：每条规则一条 `status=shadow` + `test_only` 方案；对比页默认**单开**对 V3；叠加只作可选开关，且叠加结果**不得**替代单规则结论。

### 2.1 盘口／水位族（易重叠，必须分账）

| 桶 | 含规则 | 互斥怎么切 | 说明 |
|---|---|---|---|
| A 静态深浅×水 | `N4` | 仅**初盘**（`open`）DEV×高水，**不含**升盘过程 | 与 S2 共享「高水」语义，故分账 |
| B 动态升盘 | `S2` | 仅「低开升盘→下」与「高开升盘+高水→上」两条支路，支路内再分账 | 与 N4 联测时各记一行，禁止合并 PnL |
| C 三段不动 | `S1` | 「**初盘／中盘／临盘**（`open`/`mid`/`close`）三段不动 ∩ 主水在 S1 水位带内（见 config/strategy_params.json）」；对照=同盘口档但有变动 | 与 B 几乎正交；若同场命中 A/B，报告里标 `multi_hit`，PnL 仍分账 |
| D 顺分布排除 | `N1` | 1X2 **初盘／中盘→临盘**高水等条件；方向与 V3 冲突时仍单独记 | 与 A/B/C 不同维，可并行，但同场多命中只标不合并 |
| E 单拉平阻 | `N3` | 与 N1 同用 1X2，但触发条件不同；同场双命中→`multi_hit`，分账 | 对照=信心足+顶平 |

同场多规则命中时：每条规则各自计 `hits`；另维护全局 `multi_hit_count`（可选）。**禁止**把多规则合成一条「组合影子」当主结论。

### 2.2 过滤层（不选边）

| 桶 | 规则 | 口径 |
|---|---|---|
| F 滤镜 | `S8` | 只输出「跳过 / 不跳过」；评估对象= **滤后 V3** vs **未滤 V3**（ROI、回撤、命中数变化），不单独报选边胜率 |

S8 与 A–E **正交**：先跑 V3 选边，再套 S8 决定是否下单。

### 2.3 模型／价值族

| 桶 | 规则 | 口径 |
|---|---|---|
| G 泊松偏差 | `N5` | 与盘口叙事族分账；必报 CLV 三列（**一律以平博为准**，见下） |
| H 滚球 stub | `IP-B` → 再 `IP-A` | IP-A 依赖 IP-B 底座；未完成 B 前 A 不评 ROI |
| I xG stub | `XG-BSD-1` | 特征接入后再挂；覆盖缺口单独记，不与 A–E 合并 |

### 2.4 暂缓

- `N2`：`blocked_need_median_table`，无中庸平表前不进影子、不算样本门槛。

## 3. 最少样本门槛（门槛未满：只报 hits/coverage，不宣称跑赢 V3）

以**单规则、单方向支路**为单元（S2 的两条支路各算一套门槛）。

| 阶段 | `hits` 下限（经验） | 同时要求 | 允许结论 |
|---|---|---|---|
| L0 冒烟 | ≥ 20 | `n_eligible` ≥ 50 | 规则能跑通、无泄漏；不比 V3 |
| L1 可谈方向 | ≥ … | `coverage` 稳定（连续两周波动不大）且走水占比单独列出 | 可报相对 V3 的命中差／ROI **点估计**，须带「样本不足」标签 |
| L2 可对照宣称 | ≥ 150 | 或日历到汇报日 **2026-11-06** 且 hits≥100（取严者） | 才允许「优于 / 不劣于 V3」类措辞；建议同时报 CLV（规则）均值，并附 CLV（真实）／CLV（收盘）副表 |

说明：

1. AH 半赢半输按 0.5 权计入有效结算场，但 `hits` 仍按触发场计 1。  
2. 过滤层 S8：把「滤后仍下注」场数当作类 `hits`；门槛用「滤后下注场」对照上表 L0/L1/L2。  
3. 稀有桶（S1、N4 深开）若到汇报日仍 < L1：延期汇报日，**禁止**用叠加或放宽阈值凑样本。  
4. 阈值（DEV±…、主水带、δ、来回次数 N 等）须在首次跑影子前写入方案 config／指纹；改阈值 = 新 `config_fingerprint`，样本重新累计。特征所取盘口**阶段**也写入指纹；阶段一换 = 新规则、样本重计（详见 [`shadow-walkforward-twdecay-v1-cli-fingerprint.md（未公开）`](./shadow-walkforward-twdecay-v1-cli-fingerprint.md（未公开）) §4.1）。旧 V3／手工阈值若锚定 11:10，指纹阶段记 `live@11:10`，勿写成 `open`／`mid`／`close`。

## 4. 建议实验顺序（到 2026-11-06）

1. **先**：S1、S2（两支路分账）、S8（滤 V3）— 用户优先。  
2. **并行**：N4（与 S2 分账）、N1、N3。  
3. **N5**：数据依赖齐后单独跑，CLV 三列必报（主看规则，市场对照看真实／收盘）。  
…. **IP / XG**：stub 只体检数据覆盖，不进与 V3 的 ROI 对决，直到 L0 冒烟通过。
